# Agent Note: 精确制种文件选择与快照边界

Status: proposed

## Problem

文件树取消勾选必须精确排除指定文件；不能把选择列表当作普通 glob。mkbrr 的筛选大小写不敏感、支持通配符及逗号分组，不能可靠表示所有字面文件名。预览后新增文件也不能无提示进入已经确认的选择。

## Proposal

普通无筛选制种继续使用 mkbrr；精确选择与自定义排除使用共享扫描清单，选中文件按路径逐字匹配。快照绑定源目录、有效规则及完整扫描元数据，选中和未选文件变化都会使已应用的选择失效；执行前与哈希结束后检查，取消或校验失败不发布新种子。

文件树默认选择规则允许的全部文件，目录操作包括折叠和搜索隐藏项。搜索只影响显示，应用不立即开始任务。主操作与快捷制种有独立草稿，按源路径隔离；关闭弹窗丢弃未应用修改。规则命中项不可通过勾选绕过，必须先改规则。空用户规则与缺省跟随配置在 API 上分开表达。

新精确路径使用流式标准 v1 分块与现有 go-torrent bencode/metainfo 编码，不复制媒体、不建立链接临时树。普通无筛选路径保留 mkbrr 的 tracker 规则及现有行为。筛选路径的自动分块策略必须在文档中标明差异，不能声称自动得到与普通制种相同的 InfoHash。

相关笔记当场审计：[单二进制架构](../../implemented/architecture/2026-10-31-single-static-binary.md)部分重叠，原本否决全量自写制种的理由仍成立，此处只为精确文件集合建立窄路径；[文件导航与结果](../../implemented/feature/2026-10-31-file-navigation-and-results.md)部分重叠，沿用快捷参数独立草稿，不改变导航及结果持久化原则。其他活跃上传、发布与凭据笔记无关，没有需要淘汰的旧文件选择提案。

## Alternatives considered

- 直接复用 mkbrr IncludePatterns 最轻量且可继承 tracker 优化，但大小写折叠、特殊字符及分组语义不能保障所有字面路径精确性，故不作为手动选择契约。
- 临时目录复制或软硬链接后调用 mkbrr 可复用完整算法；复制视频的存储成本过高，硬链接跨卷失败，Windows 软链接权限和生命周期增加部署负担，故不采用。
- 全部制种改为新实现能统一逻辑，但破坏既有 InfoHash 与 tracker 优化的风险没有必要，无筛选路径保留原实现。

## Acceptance criteria

实际生成并解析 torrent，逐项对比路径、长度和跨文件拼接的 SHA-1 分块。验证特殊字符、大小写、中文、规则三种模式、空选择、快照变化及取消。API 必须登录且使用现有根目录沙箱。浏览器验证主/快捷入口、目录三态、搜索、规则禁用、取消、应用与手机布局。

## Risks

快照依赖元数据，不是完整内容哈希，也不承诺防御保留元数据的恶意并发修改。筛选路径与 mkbrr 的自动分块策略不同；辅种必须使用相同文件集合和分块参数。目录扫描有资源上限，应明确报错而非让截断清单可应用。筛选流程不支持符号链接，避免源目录外内容泄漏。
