# Agent Note: 图床结果保序与凭据隔离缓存

Status: implemented

## Problem

串行上传将每次尝试等同于整项任务成功，无法安全支持部分失败、并发完成和定点重试。重复图片反复占用图床配额。浏览器登录态图床还引入了公开 API Key 之外的凭据发送边界。

## Decision

上传适配器只处理图床协议，Engine 处理并发、重试与持久缓存，服务端负责将结果回填截图索引。Result 的 Index 指向本次输入中的原位置；回调可以按完成顺序执行但必须串行，每个输入恰好一个终态。补传将输入索引映射回原截图，不能过滤失败结果后再与完整数组配对。部分失败与取消保留成功链接及完整逐项状态，同时任务不能显示全部成功。

缓存对实际上传字节计算 SHA-256，以图床、端点、凭据身份摘要和内容摘要区分身份，避免换账号后错误复用。成功写入持久缓存，失败不缓存；同批相同图片只上传一次。强制重传绕过跨批缓存，但仍保留同批去重。没有服务端已有链接时，不追加空字节绕过重复检测。

每项最多三次尝试；确定认证失败不重试。已发送请求后等待响应超时的结果不确定，不自动重复提交。重试失败项保持已成功项原位置。BBCode 从成功截图按原序生成，不虚构缩略图链接；部分成功的复制操作必须明示范围。

公开图床包含 PicGo、Pixhost、ImgBB、Freeimage、AGSV。PterClub 仅固定图床域名 Cookie 认证，获取 auth_token 后上传，拒绝跨域重定向，失效最多重新获取一次。M-Team、Postimages、浏览器自动登录和 PT 发布页填充不在本轮范围。真实图床上传不是模拟测试的一部分，需另行取得凭据及外部写入授权。

普通设置快照仍脱敏，完整凭据只在已登录的显式 POST 请求中按需读取且 no-store。沿用[设置密钥按需显隐](../../implemented/bug-fix/2026-11-04-settings-secret-reveal.md)的草稿生命周期；该决定扩展到多图床，不取代既有原则。现有笔记检索仅发现该相关记录和[单二进制架构](../../implemented/architecture/2026-10-31-single-static-binary.md)中的上传模块说明，没有其他上传缓存提案；图标缓存与本决定无关。

## Alternatives considered

- 只增加图床下拉，继续串行 UploadAll，改动最小；但不能满足逐项重试与结果保序，失败项错位仍可能发生。
- 只用文件哈希缓存，命中率更高；但跨账号与端点复用会越过用户选择的存储身份，故加入凭据身份摘要。
- 上传超时一律重试，可减少手工操作；但服务端可能已接收图片，自动重试会产生重复上传，因此对结果不确定的尝试保留人工决策。
- 集成浏览器会话自动获取 Cookie 能减少手工填写；但扩大权限与生命周期复杂度，采用用户手动提供、固定域名发送的边界。

## Testing

- 模拟 HTTP 请求覆盖各图床协议、异常状态、限流、取消、重试与 PterClub 重定向边界。
- 并发乱序完成、部分失败后补传和同批去重不改变原始截图对应关系。
- 缓存重启可复用，凭据变化隔离，缓存文件不含明文凭据。
- 普通设置响应不暴露凭据，完整读取需要已登录 POST，并且没有缓存。
- 前端通过代表性函数及浏览器交互验证格式、失败提示、设置重开与窄屏布局。

本地验证覆盖 Go 全包测试、upload/server/task 竞态测试、前端 Node 测试及语法检查。浏览器使用独立临时数据目录验证首次设置、图床切换、凭据读取、保存后重开脱敏，以及含一项失败的三图结果和 BBCode 保序；390px 设置与结果页面通过交互与宽度测量检查，不替代视觉审查。真实服务可用性与 Cookie 风控未验。

## Consequences

图床的真实网络可用性、限额与服务端风控不由模拟测试证明。PterClub 防盗链可能限制跨站展示。Cookie/API Key 存放配置文件不等于加密存储，部署需限制数据目录权限并使用 HTTPS。持久缓存会增长，当前不新增自动清理或存活探测；链接失效时显式强制重传。
