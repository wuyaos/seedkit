# Agent Note: 设置密钥的按需显隐

Status: implemented

## Problem

设置快照只携带 API Key 掩码；仅切换 input 的 password/text 类型不能恢复完整值。直接把快照改成明文会使页面初始化、其他配置读取也收到不需要的密钥。

## Decision

普通 GET /api/settings 继续脱敏。完整 picgo Key 通过已有登录中间件保护的 POST /api/settings/picgo-key 按需读取，响应使用 Cache-Control: no-store。前端只在点击显隐且草稿仍为掩码时请求，手动输入的新 Key 不会被服务器旧值覆盖；响应到达时若已关闭或重新打开设置，则丢弃旧响应。此能力不改变保存时保留掩码/空值的既有规则。

## Alternatives considered

- 在设置快照直接返回明文，可省去一次请求，但扩大密钥传递面；因此保留快照掩码并单独按需读取。
- 只切换 input 类型最简单，但浏览器从未收到完整 Key，无法满足显示原值的需求。

## Consequences

显隐原值增加一次已登录请求，失败时保留草稿并显示错误。隐藏只改变展示类型，明文在本次设置草稿中保留，重新打开设置时重新获得掩码。no-store 不替代传输加密；对公网使用仍需要 HTTPS。

设置表单的局部 `c` 必须通过 getter 跟随 `set.c`，不能用 `x-data="{c:set.c}"` 做一次性别名。窗口重开会替换 `set`，旧别名使输入框继续展示上次的快照，甚至导致编辑和保存对象不一致；浏览器回归应覆盖连续两次打开后显隐与草稿同步。

新增路由测试覆盖未登录拒绝、GET 方法拒绝、快照脱敏、显式完整读取与禁止缓存；浏览器验收使用本地测试 Key，不打印真实密钥。现有笔记检索未发现同主题决策；文件导航笔记约束 Home 的本地偏好，与本决定互不替代。
