# 图床上传与结果导出

## 图床与认证

公开接口适配包括 PicGo、Pixhost（`.to` / `.cc`）、ImgBB、Freeimage、AGSV。除 Pixhost 外均需在设置中填写对应 API Key 或 Token；AGSV 使用 Token，不保存图床账号密码。PterClub 使用图床域名的 Cookie，属于登录态适配，不是公开匿名上传。

这里的 PicGo 指 `www.picgo.net` 图床 API，不是本地 PicGo 客户端。PterClub 的 Cookie 应属于 `s3.pterclub.net`；主站 Cookie 不一定可用。服务器出口 IP、图床风控、登录有效期及防盗链可能导致浏览器可用而服务器不可用，不能用模拟测试通过证明真实账号可上传或图片可跨站展示。

设置页切换图床不会清空其他图床已保存的凭据。普通配置读取只返回掩码，点击显隐时才按需读取完整值。未修改的掩码和空白值保留已有凭据，因此空白输入不是清除凭据的操作。

**远程使用必须配置 HTTPS，并限制数据目录访问权限。** 密码框遮罩和配置响应脱敏不等于传输加密，也不等于配置文件加密存储。不要把 Cookie、Key 或含凭据的配置文件贴入日志、问题反馈、公开仓库或截图。

## 顺序与重试

结果以原截图顺序为准，不以网络完成顺序为准。单张失败不会丢掉其他图片的成功链接。结果区显示各项状态、尝试次数和错误；任务部分失败时不能视为全部成功。

- **补传失败项**：仅上传没有成功链接的项，结果回填原位置。
- **强制全部重传**：上传全部截图并绕过跨批缓存，可能消耗图床配额；同一批次相同字节仍合并上传。
- **取消**：停止新请求并尝试取消进行中的请求。已经收到的成功结果继续保留；远端已经接收但本地未收到响应的上传无法撤销。

自动重试最多三次尝试（含首次）。认证错误、格式错误等不会盲目重试；限流和明确可重试的服务端错误采用有上限的等待。请求发送后等待响应超时可能意味着图床已经收到图片，该项标记结果不确定，应先检查图床再决定是否手工重传。

## 缓存

缓存根据实际上传图片字节的 SHA-256 复用成功链接，并区分图床、接口地址和凭据身份。压缩或图片内容改变、切换账号、切换端点均不会错误命中旧身份的缓存。重启后缓存仍可复用。

失败不写成功缓存；同一批中的相同内容只上传一次。缓存不自动探测远端链接是否还有效，遇到链接失效时可强制重传。清除本地缓存也不会删除图床上的图片。工具不会通过追加空字节绕过图床重复检测。

## 复制与 BBCode

- 纯链接：每行一个原图 URL。
- 原图 BBCode：`[img]原图URL[/img]`。
- 缩略图 BBCode：`[url=原图URL][img]预览图URL[/img][/url]`。

缩略图格式只在图床确实返回预览图时可用，不猜测缩略图地址。复制只包含成功项并保持原始相对顺序；部分失败时会明确提示复制范围，不插入空标签或用另一张图片填充失败位置。

本轮不包含 M-Team、Postimages、浏览器自动登录、Cookie 自动提取、验证码处理或 PT 发布页自动填写。真实图床上传需另行提供凭据并确认外部写入授权，开发测试使用模拟响应。
